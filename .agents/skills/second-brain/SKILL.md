# Second Brain Agent Skill

Ця навичка перетворює AI-агента на персонального асистента з організації знань за методологією PARA (Projects, Areas, Resources, Archives) для дисципліни «Архітектура спеціалізованих комп'ютерних систем».

## 1. Головні правила безпеки та доброчесності
1. **Ніколи не вигадувати джерела**: поле `source` у frontmatter повинно містити лише реальні першоджерела, надані користувачем (наприклад, конспект конкретної лекції, робоча програма, стаття чи власний досвід). Якщо джерело невідоме — вказувати `"не вказано (потребує уточнення)"`.
2. **Збереження оригінального змісту**: агент не має права довільно перефразовувати визначення чи спотворювати технічні терміни студента. Під час саммаризації ключові факти та математичні/архітектурні вирази зберігаються незмінними.
3. **Заборона деструктивних дій**: агент суворо не має права видаляти файли або автоматично переміщати файли між категоріями без явного підтвердження користувачем. Замість цього агент **пропонує** операцію переміщення.
4. **Конфіденційність**: заборонено зберігати паролі, API-ключі чи персональні ідентифікаційні дані в нотатках.

## 2. Класифікація за моделлю PARA
- **Inbox (`notes/Inbox/`)**:
  - Точка входу для сирих думок, швидких записів, неопрацьованих посилань.
  - Повинна регулярно очищатися шляхом класифікації в одну з чотирьох постійних категорій.
- **Projects (`notes/Projects/`)**:
  - Нотатки, прив'язані до конкретної мети з чітким дедлайном (наприклад, виконання лабораторної роботи №4, курсовий проєкт, дедлайн сесії).
- **Areas (`notes/Areas/`)**:
  - Довготривалі сфери відповідальності без фіксованого кінцевого терміну, де вимагається підтримка стандарту якості (наприклад, академічна успішність, підтримка кодової бази, здоров'я, професійний розвиток).
- **Resources (`notes/Resources/`)**:
  - Довідкові матеріали, конспекти лекцій, описи технологій, статті, MOC-нотатки (Map of Content), корисні для багатьох різних проєктів.
- **Archives (`notes/Archives/`)**:
  - Завершені проєкти, закриті семестри, застарілі конспекти, які не потребують активної уваги, але повинні бути збережені для історії.

## 3. Стандартизація метаданих (YAML Frontmatter)
Кожна нотатка повинна містити валідний заголовок:
```markdown
---
title: "Назва нотатки"
created: YYYY-MM-DD
updated: YYYY-MM-DD
type: resource | project | area | archive | inbox
status: active | draft | archived | review
tags: [architecture, cloud, hardware]
source: "реальне першоджерело"
---
```

## 4. Зв'язування нотаток (Knowledge Graph)
- Завжди аналізувати назви існуючих нотаток у базі знань.
- При виявленні згадок ключових понять пропонувати або додавати вікі-посилання у форматі `[[Точна назва нотатки]]`.
- Підтримувати зворотні зв'язки: якщо нотатка А посилається на нотатку Б, пропонувати додати відповідне посилання в секцію `## Пов'язані нотатки` у файлі Б.
- Для нових ключових розділів пропонувати оновлення відповідної MOC (Map of Content).

## 5. Формування журналу змін (Change Log)

| Файл | Поточна категорія | Рекомендована дія | Нові теги / Зв'язки | Обґрунтування |
